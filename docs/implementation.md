# План первого вертикального среза (предложение)

> План не означает, что задачи выполнены. Стадии проверяются независимо.

## Этап 0 — уточнить контракт

- Сверить §§12.9–12.23 мастер-концепции и §9 технического ТЗ с `docs/dungeons.md`.
- Отметить, какие сценарии зависят от D-P01, D-P02, D-T02.
- Определить минимальный стабильный API MobDifficulty, Protection, WorldProgression, Rewards без прямого SQL в чужие модули.

## Этап 1 — собрать каркас плагина

- Gradle/Java 25, проверить существование зависимостей Purpur/Paper 26.2.
- `plugin.yml`, конфиги, загрузка/отключение, logger, permissions, диагностика.
- Компиляция, smoke-test загрузки и выключения на целевой версии.

## Этап 2 — жизненный цикл

- `Dungeon Template`, `Dungeon Run`, `Attempt ID`, блокировка конкурентного запуска.
- Состояния `AVAILABLE`, `RESERVED`, `RUNNING`, `COMPLETED`, `FAILED`, `RESETTING`, `COOLDOWN`, `DISABLED`, `ERROR`.
- Снимок участников/версии правил и серверная проверка переходов.
- Сохранение и корректный рестарт.

## Этап 3 — первый защищённый данж

- Физический вход, защищённая зона, контроль комнат и интерактивных объектов.
- Один малый сценарий без процедурной генерации; геометрия/координаты конфигурируемы.
- Обработка заблокированных входов, смерти, выхода и сторонних телепортов.

## Этап 4 — награды и восстановление

- Персональное право на лут, устойчивые Operation ID, безопасная выдача после победы.
- Очистка сущностей, блоков, механизмов, закрытие доступа при ошибке.
- Кулдаун и проверка целостности шаблона.

## Этап 5 — тесты

- Unit-тесты состояния попыток, наград, кулдаунов, сериализации.
- Интеграционные тесты с реалистичными плагинами/обработчиками.
- Runtime-прогоны на Paper/Purpur 26.2: 2 группы, рестарт, краш во время выдачи, восстановление чанков.
- После результатов обновить фактический статус.

**Не включать без отдельного решения:** случайную сборку комнат, матчмейкинг, сезонные расширения, большой набор новых боссов.
